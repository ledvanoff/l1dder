# L1DDER — Цепочка 2: Фича и Спека (`/l1-feature`)

> **ПРАВИЛО ДЛЯ МОДЕЛИ:** Выполняй инструкцию строго по шагам 1 → 2 → 3 → 4 → 5. Не пропускай шаги. Каждая фича `FEAT-NNN` обязана быть жёстко привязана к родительской идее `IDEA-NNN`. Никогда не создавай файлы до слова «ок» от пользователя на Шаге 3.

---

## Справочник форматов ID и статусов (копируй символ-в-символ)

- **Родительский ID идеи:** `IDEA-NNN` (должен существовать в `docs/ideas.md`).
- **Единый ID фичи и спеки:** `FEAT-NNN` (три цифры: `FEAT-001`, `FEAT-002`...).
- **Имя папки спеки:** `docs/specs/FEAT-NNN-<slug>/` (строго начинается с `FEAT-NNN-`, например `docs/specs/FEAT-001-catalog-search/`).
- **ID шагов внутри фичи (до планирования спринта):**
  - Обычные задачи: `FEAT-NNN.01`, `FEAT-NNN.02`, `FEAT-NNN.03`...
  - **Обязательная финальная задача каждого спринта:** `FEAT-NNN.99` (`Гигиена спринта и Doctor Checklist (E2E + UAT + Docs Sync)`).
- **Статус `FEAT-NNN` после записи в бэклог:** `📋 в бэклоге`
- **Статус родительской `IDEA-NNN` после создания фичи:** меняется с `📋 нереализована` на `🚧 реализация`

## ШАГ 2: Проверь родительский `IDEA-NNN` и вычисли `FEAT-NNN`

1. **Определи `IDEA-NNN`:**
   - Если пользователь указал `IDEA-NNN` — найди её в `docs/ideas.md`.
   - Если пользователь не указал ID — возьми первую идею со статусом `📋 нереализована` из `Discovery Queue` в `docs/roadmap.md` (или из `docs/ideas.md`).
   - Если пользователь принёс совсем новую идею, которой нет в `docs/ideas.md` — сначала присвой ей следующий `IDEA-NNN` и включи её регистрацию в `docs/ideas.md`.
2. **Вычисли `FEAT-NNN`:**
   - Посмотри Таблицу 1 («1. Реестр Фич») в `docs/backlog.md`.
   - Найди наибольший номер `FEAT-NNN` и прибавь `+1` (если таблица пустая — `FEAT-001`).

## ШАГ 3: Опрос `grilling` + Проектирование `codebase-design` + Декомпозиция `FEAT-NNN.01..99` (`⛔ СТОП`)

1. **Закрой открытые развилки через `grilling`:** если перед написанием спеки остались продуктовые или архитектурные развилки, задай их в формате:
   ```markdown
   ❓ **Q1 — [Название развилки]**: [Варианты + факты]
   ➡️ **Рекомендация:** [Рекомендуемый вариант, который принимается словом «ок»]
   ```
2. **Спроектируй глубокие модули и швы (`codebase-design` + `tdd`):**
   - Определи, какие **глубокие модули (`Deep Modules`)** создаются или меняются (много логики за простым публичным интерфейсом `Interface`).
   - Проверь каждый новый модуль **тестом на удаление (`Deletion Test`)** и правилом *«1 адаптер = выдуманный шов, 2 адаптера = реальный шов»*.
   - Зафиксируй **публичные швы для тестирования (`Pre-agreed Test Seams` для `tdd`)** — какие именно публичные функции/методы будут покрыты тестами и что эти тесты ловят.
3. Выведи пользователю в чат сводку спеки на согласование:

```markdown
### Проект фичи и спеки `FEAT-NNN`

| Поле паспорта | Значение |
|---------------|----------|
| **ID фичи / спеки** | `FEAT-NNN` |
| **Родительская идея** | `IDEA-NNN` ([Название идеи]) |
| **Папка спеки** | `docs/specs/FEAT-NNN-<slug>/` |
| **Приоритет** | `P0` / `P1` / `P2` / `P3` |
| **Статус после утверждения** | `📋 в бэклоге` |

#### 1. Требования (`requirements.md`)
- **US-1:** As a ... I want ... So that ...
  - `GIVEN ... WHEN ... THEN ...`

#### 2. Технический дизайн и Швы (`design.md` — `codebase-design` & `tdd`)
- **Глубокие модули и их публичный интерфейс (`Interface`):** `...`
- **Согласованные публичные швы для тестов (`Pre-agreed Test Seams`):**
  - `Seam 1`: `[модуль/функция]` — что проверяем и что это гарантирует.
- **Схемы данных / контракты:** `...`

#### 3. Декомпозиция на кандидаты спринтов и шаги (`tasks.md` и `docs/backlog.md`)
**Кандидат спринта 1 (`SPRINT-??` — номер получит в `/l1-planning`):** [Цель спринта]
| ID шага спеки | ID задачи спринта | Тип | Название задачи |
|:-------------:|:-----------------:|:---:|-----------------|
| `FEAT-NNN.01` | — *(до `/l1-planning`)* | `feat` | [Задача 1] |
| `FEAT-NNN.02` | — *(до `/l1-planning`)* | `feat` | [Задача 2] |
| `FEAT-NNN.99` | — *(до `/l1-planning`)* | `chore` | **Гигиена спринта и Doctor Checklist (E2E + UAT + Docs Sync)** |
```

4. ⛔ **СТОП:** Спроси: *«Утверждаем спеку `FEAT-NNN` (связанную с `IDEA-NNN`), публичные швы тестирования и декомпозицию (ок / правки)?»* и жди ответа.
