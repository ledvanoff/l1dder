## 1. Контекст и связь с идеей `IDEA-004`

В любом проекте регулярно возникают служебные работы, не меняющие поведение продукта для его пользователей: настройка CI/CD, обновление зависимостей, скрипты сборки, git-хуки, линтер, тесты, `Makefile`, правила для ИИ-агентов. Сейчас в `L1DDER` для них нет штатной команды: `/l1-task` требует активного спринта в `docs/roadmap.md`, а `/l1-hotfix` предназначен для срочных багов с `RED Reproduction Gate`. В результате служебные правки либо остаются без следа в трекере, либо описываются вручную только во внутреннем `30-tech-stack.mdc` самого репозитория `L1DDER`.

Фича `FEAT-005` выносит уже обкатанный нами внутри репозитория процесс `CHORE-NNN` в штатную команду `/l1-chore` для всех пользователей фреймворка на русском и английском языках.

## 2. Целевая аудитория / Роли

- Пользователь `L1DDER`, которому нужно быстро и с контролем («ок») выполнить служебную правку проекта без создания идеи, спеки и спринта в роадмапе.
- ИИ-агент, который обязан отличить служебную правку от продуктовой фичи/бага, не ослабляя `Roadmap Gate`.

## 3. User Stories и Acceptance Criteria

### US-1: Защита границы «служебная правка vs продукт»
- `GIVEN` пользователь вызывает `/l1-chore` `WHEN` запрошенное изменение меняет поведение продукта для его пользователей (новая пользовательская возможность, изменение публичного API/CLI/UI или починка продуктового бага) `THEN` агент **останавливается до любых правок файлов** и предлагает `/l1-task` (или `/l1-idea` / `/l1-feature`) либо `/l1-hotfix`.

### US-2: Короткий цикл с одной остановкой (`⛔ СТОП`)
- `GIVEN` запрошена служебная правка внутренней кухни проекта (CI, зависимости, скрипты, хуки, тесты, `Makefile`, настройки окружения или агентов) `WHEN` агент прочитал `docs/backlog.md` и вычислил следующий номер `CHORE-NNN` `THEN` он предлагает варианты реализации с рекомендацией по `ponytail`, показывает карточку `CHORE-NNN` и ждёт одного подтверждения **«ок»** (`⛔ СТОП`).
- `GIVEN` пользователь ответил «ок» `WHEN` агент выполняет правку `THEN` нетривиальная логика покрывается тестами по срезам (`tdd`), запускается `make ci` (0 ошибок), и в раздел 4 файла `docs/backlog.md` добавляется строка `CHORE-NNN` (4 колонки: `ID правки | Дата | Что и зачем | Сообщение коммита`).

### US-3: Автодобавление журнала `CHORE-NNN` в существующих проектах
- `GIVEN` проект был инициализирован на предыдущей версии `L1DDER` и в его `docs/backlog.md` ещё нет раздела `## 4. Журнал служебных правок (CHORE-NNN)` (`## 4. Chore Log (CHORE-NNN)`) `WHEN` выполняется `/l1-chore` `THEN` агент сам добавляет этот раздел с таблицей из 4 колонок в конец `docs/backlog.md` и записывает `CHORE-001`.

### US-4: Стандарт ID, исключение в `Roadmap Gate` и синхронизация счётчиков
- `GIVEN` правила (`00-methodology.mdc`, `20-workflow.mdc`, `40-skills-router.mdc`), сводка в `src/agents.ts`, словарь `GLOSSARY.md` и документация на RU и EN `WHEN` описывается `Roadmap Gate` `THEN` явно названы оба законных исключения вне очереди спринтов: `/l1-hotfix` (срочный баг) и `/l1-chore` (служебная правка без изменения поведения продукта).
- `GIVEN` манифест `skills.json`, CLI (`src/agents.ts`, `src/installer.ts`), документация и тесты `WHEN` перечисляются скиллы и команды `THEN` в коробке **21 встроенный скилл** (8 в секции `l1dder` + 4 `ponytail` + 9 `mattpocock/skills`) и **7 пользовательских слэш-команд** (`/l1-onboard`, `/l1-idea`, `/l1-feature`, `/l1-planning`, `/l1-task`, `/l1-hotfix`, `/l1-chore`, плюс `/l1-evo` для эволюции самой методологии).

## 4. Ограничения и инварианты

- Русская и английская версии скилла `/l1-chore`, шаблона `backlog-template.md`, правил и гайдов меняются синхронно.
- Триггером скилла служит как вызов `/l1-chore` (`$l1-chore` / `@l1-chore`), так и словесная просьба пользователя в чате сделать служебную/`chore`-правку.
- Пользовательский `docs/backlog.md` при `npx l1dder update` не перезаписывается: раздел 4 появляется у новых проектов из шаблона `backlog-template.md`, а у существующих — автоматически при первом вызове `/l1-chore`.

## 5. Out of scope (Что НЕ делаем по принципу `ponytail` / YAGNI)

- Автоматический анализатор кода/диффа для определения границы «продукт или служебная правка» — граница задаётся явным правилом в скилле и согласуется с человеком на `⛔ СТОП`.
- Отдельные папки, спеки, спринты, `plan.md` или `summary.md` для `CHORE-NNN`.
- Изменение `site/.vitepress/og-card.html` (на превью-карточке изображены только 4 ступени основной лестницы: `/l1-idea` → `/l1-feature` → `/l1-planning` → `/l1-task`).
