## 1. Контекст и связь с идеей `IDEA-006`

Сейчас `/l1-onboard` согласует стек в шаге 2, до любой работы над идеей, а затем в шаге 3 показывает все шесть файлов `docs/concept/` одной сводкой с одной остановкой. Шаблон `vision.md` при этом забирает работу у архитектуры, модели данных и стека. Человек получает большую портянку текста и вопросов. Фича прорабатывает концепт по одному файлу и ставит стек после архитектуры.

Перед релизом встроенные скиллы `ponytail` и `mattpocock/skills` сверяются с исходниками: у ponytail вышла переработка «Ponytail 5», а в `writing-for-agents` и `diagnosing-bugs` уже есть ссылки на файлы, которых нет в поставке.

## 2. Целевая аудитория / Роли

- Новый пользователь L1DDER, который начинает проект с нуля или подключает проект с кодом.
- ИИ-агент, который ведёт онбординг: в том числе быстрые и недорогие модели, поэтому скилл должен быть коротким и пошаговым.

## 3. User Stories и Acceptance Criteria

### US-1: Сначала идея, потом стек
- `GIVEN` пустой проект `WHEN` пользователь вызывает `/l1-onboard` `THEN` первое сообщение начинается с «Этап 1 из 6: идея» и не спрашивает про стек.
- `GIVEN` концепт пройден `WHEN` начинается этап 5 `THEN` агент предлагает стек, опираясь на `architecture.md`.

### US-2: Один файл за раз
- `GIVEN` любой этап `WHEN` агент задаёт вопросы `THEN` их не больше 7, у каждого есть рекомендация и варианты, и все они касаются только файла этого этапа.
- `GIVEN` этап `WHEN` пользователь сказал «ок» на черновик `THEN` записывается один файл, и агент переходит к следующему этапу.
- Порядок этапов: 1 идея (`idea.md`), 2 видение (`vision.md`), 3 архитектура (`architecture.md`; `integrations.md` и `api-contracts.md` только если нужны), 4 модель данных (`data-model.md`), 5 стек (`30-tech-stack.mdc`, `40-skills-router.mdc`, `Makefile`, стек-скиллы), 6 банк идей, бэклог, роадмап и `docs/README.md`.

### US-3: Раунд заканчивается выбором
- `GIVEN` любой раунд `WHEN` агент разобрал ответы `THEN` он говорит, что понятно, что усилить и что неясно, и спрашивает «Идём дальше или ещё раунд?» со своей рекомендацией.
- Жёсткого лимита раундов нет: решает пользователь.
- В начале каждого сообщения агент пишет, где находится пользователь, например «Этап 2 из 6: видение, раунд 1».

### US-4: Сведения для другого файла не теряются
- `GIVEN` ответ касается другого файла `WHEN` пользователь сказал «ок» на предложение агента `THEN` в тот файл сразу записывается заметка, и на его этапе агент начинает с неё.

### US-5: Проект с кодом
- `GIVEN` в проекте есть код `WHEN` идёт любой этап `THEN` агент заполняет черновик по коду, а файлы вроде `CLAUDE.md`, `AGENTS.md` и `.cursor/rules/` читает только вспомогательно и ничего в них не меняет.
- `GIVEN` вспомогательные файлы расходятся с кодом `WHEN` агент готовит черновик `THEN` он опирается на код и показывает расхождение.

### US-6: Прерванный онбординг продолжается
- `GIVEN` часть файлов `docs/concept/` уже есть `WHEN` пользователь снова вызывает `/l1-onboard` `THEN` агент продолжает с первого незавершённого этапа.

### US-7: Каждый этап опирается на свои скиллы
- `GIVEN` любой этап `WHEN` агент его начинает `THEN` он читает через `Read` скиллы этого этапа:

| Этап | Скиллы |
|---|---|
| 1. Идея | `grilling`, `domain-modeling`, `prototype` по необходимости |
| 2. Видение | `grilling`, `domain-modeling`, `prototype` по необходимости |
| 3. Архитектура | `codebase-design` (с `DESIGN-IT-TWICE.md`), `domain-modeling` (`ADR-FORMAT.md`), `ponytail` |
| 4. Модель данных | `domain-modeling`, `codebase-design` |
| 5. Стек | `ponytail`, `tdd`, `writing-for-agents`, стек-скиллы из `skills.json` |
| 6. Банк идей и роадмап | `grilling` |

### US-8: Встроенные скиллы актуальны и целы
- `GIVEN` встроенный скилл из `ponytail` или `mattpocock/skills` `WHEN` выходит релиз `THEN` его содержание совпадает с исходником на зафиксированном коммите, кроме записанных правок под L1DDER.
- `GIVEN` любой поставляемый скилл `WHEN` в нём есть относительная ссылка на файл `THEN` этот файл есть в поставке.

## 4. Ограничения и инварианты

- Русская и английская версии скилла меняются синхронно и имеют одинаковое число шагов и остановок.
- Цикл этапа описан в скилле один раз, а не повторяется для каждого этапа.
- Пользовательские файлы `docs/` при `npx l1dder update` не трогаются, поэтому у настроенных проектов ничего не ломается.
- `npx l1dder skills update` для сверки встроенных скиллов не используется: он затирает правки под L1DDER ([`ADR-0001`](../../adrs/ADR-0001-bundled-skills-merge.md)).

## 5. Out of scope (Что НЕ делаем по принципу `ponytail` / YAGNI)

- Новые шаблоны концепта, кроме сокращения `vision.md`.
- Отдельную команду для каждого этапа и жёсткий лимит раундов.
- Вызов встроенного `/init` агентов и правки в чужих файлах инструкций.
- Сохранение прогресса между сессиями: агент видит, какие файлы `docs/concept/` уже есть.
- Новые скиллы `ponytail-gain` и `ponytail-help` из исходника.
