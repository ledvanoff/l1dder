## 1. Архитектурное решение

Кода здесь почти нет: поведение онбординга задаёт текст скилла `assets/i18n/{ru,en}/skills/l1-onboard/SKILL.md`. Скилл становится коротким порядком из 6 этапов с одним общим циклом:

1. Строка «Этап N из 6: <название>, раунд M».
2. Чтение скиллов этапа (US-7) и, в проекте с кодом, черновик по коду.
3. Раунд до 7 вопросов, у каждого рекомендация и варианты.
4. Разбор ответа: что понятно, что усилить, что неясно, что перенести в другой файл. Заметки в другие файлы пишутся сразу после «ок».
5. Вопрос «Идём дальше или ещё раунд?» с рекомендацией агента.
6. Черновик файла этапа, «ок», запись, переход к следующему этапу.

Цикл описан один раз: длинный текст с повтором для каждого этапа быстрые модели выполняют хуже.

Шаблон `vision.md` сокращается до системы в целом, ролей, сценариев и принципов. Архитектура, компоненты и структура проекта уходят в `architecture.md`, доменные сущности в `data-model.md`, технологии в `30-tech-stack.mdc`.

Встроенные скиллы сливаются с исходниками вручную, с сохранением правок под L1DDER ([`ADR-0001`](../../adrs/ADR-0001-bundled-skills-merge.md)).

## 2. Затрагиваемые глубокие модули и публичные швы (`codebase-design` & `tdd`)

| Модуль (`Module`) | Публичный интерфейс (`Interface` на шве `Seam`) | Что скрывает | Как тестируем |
|-------------------|-------------------------------------------------|--------------|---------------|
| `assets/i18n/{ru,en}/skills/l1-onboard/SKILL.md` | Готовый текст скилла | Порядок этапов, цикл раунда, правила для проекта с кодом | `tests/onboarding-skill.test.ts`, контракт текста |
| `assets/i18n/{ru,en}/skills/*` | Набор поставляемых файлов скиллов | Правки под L1DDER поверх исходников | `tests/bundled-skills.test.ts`, целостность ссылок |

**Согласованные публичные швы (`Pre-agreed Test Seams`):**

- `Seam 1`: в обоих языках шаги концепта идут раньше шага стека. Ловит откат к старому порядку.
- `Seam 2`: есть «до 7 вопросов» и «Идём дальше или ещё раунд?» (в английском фраза с тем же смыслом). Ловит потерю ритма.
- `Seam 3`: есть строка «Этап N из 6» и правило «первоисточник — код». Ловит потерю ориентира и правила для проекта с кодом.
- `Seam 4`: у русской и английской версии одинаковое число шагов и остановок. Ловит рассинхрон языков.
- `Seam 5`: каждый скилл, названный в онбординге, есть в поставке. Ловит ссылку на несуществующий скилл.
- `Seam 6`: каждая относительная ссылка внутри поставляемых скиллов ведёт на существующий файл. Ловит две нынешние битые ссылки (`SKILL-MECHANICS.md`, `scripts/hitl-loop.template.sh`) и будущие.

Контракт текста не проверяет поведение модели. Поведение проверяется в `FEAT-004.99`: два прогона онбординга в чистой песочнице субагентом, с нуля и с готовым кодом. Проверяется по фактам: первое сообщение не про стек, в раунде не больше 7 вопросов, каждый раунд заканчивается выбором, файлы появляются по одному в нужном порядке.

## 3. Модель данных / Схема конфига / Контракты

Новых схем нет. Меняется шаблон `vision.md`. Коммит исходника, на котором стоит наша копия, и список правок под L1DDER записываются в [`ADR-0001`](../../adrs/ADR-0001-bundled-skills-merge.md), чтобы следующую сверку можно было сделать по диффу. В `skills.json` их не пишем: пользователям эта информация не нужна.

## 4. Принятые решения и риски

| Вопрос / Развилка | Выбранное решение | Почему (обоснование) |
|-------------------|-------------------|----------------------|
| Место стека | После архитектуры и модели данных | Стек выводится из архитектуры |
| Число этапов в строке «Этап N из ...» | 6, включая банк идей и роадмап | Пользователь видит весь путь |
| Шаблон `vision.md` | Сократить | Иначе второй этап снова задаёт вопросы обо всём |
| Ритм | До 7 вопросов, вопрос «дальше или ещё раунд» после каждого, без жёсткого лимита раундов | Решение пользователя, по образцу clarify в spec-kit |
| Сведения для другого файла | Писать сразу после «ок» | Прерванный онбординг ничего не теряет |
| Проект с кодом | Те же этапы, код — первоисточник, файлы `/init` вспомогательно | Решение пользователя |
| Сверка встроенных скиллов | Первым шагом этой фичи, ручное слияние | Онбординг ссылается на свежие скиллы, один релиз |

**Риски:**
- **Ломающие изменения в «Ponytail 5».** Если что-то в новой версии ломает ожидания пользователей, это записывается в `breaking` записи релиза.
- **Модель не следует ритму.** Контракт текста этого не ловит, поэтому обязателен прогон субагентом в `FEAT-004.99`.
