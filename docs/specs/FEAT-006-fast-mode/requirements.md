| Поле паспорта | Значение |
|---------------|----------|
| **ID фичи / спеки** | `FEAT-006` |
| **Родительская идея (`IDEA-NNN`)** | [`IDEA-005`](../../ideas.md#idea-005) |
| **Запись в Бэклоге** | [`docs/backlog.md#feat-006`](../../backlog.md#feat-006) |
| **Приоритет** | `P2` |
| **Статус фичи** | `🚧 реализация` |
| **Назначенные спринты** | [`SPRINT-05`](../../sprints/SPRINT-05-fast-mode/README.md) |

## 1. Контекст и связь с идеей `IDEA-005`

Для небольшой фичи полный путь `/l1-idea` → `/l1-feature` → `/l1-planning` → `/l1-task` занимает больше времени, чем сам код: у одной задачи и `TASK-NN.99` вместе четыре остановки и `plan.md` до кода. `/l1-fast` — более автономный режим для агента: человек описывает фичу, агент уточняет и рекомендует, после одного «ок» сам реализует и проверяет всё, что проверяется в обычном пути, и приходит с результатом и сценарием ручной проверки. Реестры заполняются полностью, но после кода и с пометкой `режим: /l1-fast`.

Чтобы отказ `/l1-fast` при занятом роадмапе указывал на существующий путь, фича добавляет в `/l1-planning` отклонение текущего спринта с откатом его изменений.

## 2. Целевая аудитория / Роли

- Пользователь `L1DDER`, которому нужна небольшая фича продукта быстро и без потери качества.
- ИИ-агент, который работает автономно между двумя остановками и не пропускает ни одной проверки.
- Пользователь, который хочет отказаться от текущего спринта и вернуть код в состояние до него.

## 3. User Stories и Acceptance Criteria

### US-1: Строгий отказ при активном спринте

**As a** пользователь **I want** чтобы `/l1-fast` не запускался поверх начатого спринта **So that** в проекте не было параллельной работы и смешанных изменений.

```
GIVEN позиция 1 (CURRENT) в docs/roadmap.md занята
WHEN  вызван /l1-fast
THEN  агент строго отказывает и не меняет ни одного файла
AND   требует одно из двух: закончить текущий спринт через /l1-task
      или отклонить его с откатом всех изменений через /l1-planning

GIVEN на позиции 1 (CURRENT) стоит бронь с пометкой (режим: `/l1-fast`) прерванной сессии
WHEN  вызван /l1-fast
THEN  новую фичу поверх брони агент не начинает и не меняет ни одного файла
AND   спрашивает: продолжить эту фичу с Шага 5 или отклонить её через /l1-planning

GIVEN идёт быстрый спринт
WHEN  в соседней вкладке вызваны /l1-idea, /l1-feature или /l1-planning
THEN  они работают как обычно: отказ касается только реализации (второго /l1-fast и /l1-task)
```

### US-2: Оценка масштаба

**As a** пользователь **I want** чтобы агент честно говорил, когда фича слишком большая для быстрого режима **So that** большие решения не принимались без спеки.

```
GIVEN сработал хотя бы один признак масштабной работы:
      больше 3 задач или не хватит одного спринта;
      новая модель данных, внешняя интеграция или решение, требующее ADR;
      ломающие изменения;
      нужен отдельный разбор требований, за одно обсуждение не уложиться
WHEN  агент оценивает задачу до ⛔ СТОП №1
THEN  он предупреждает и предлагает обычный путь /l1-idea → /l1-feature
AND   решение остаётся за пользователем; если пользователь настоял, это записывается в итог

GIVEN объём вырос в процессе реализации
WHEN  агент это заметил
THEN  он останавливается и оценивает масштаб заново
```

### US-3: Две обязательные остановки и автономная работа между ними

**As a** пользователь **I want** решать только то, что могу решить только я **So that** фича делалась быстро, а качество не страдало.

```
GIVEN пользователь описал фичу в /l1-fast
WHEN  агент уточнил развилки (grilling), проверил признаки масштаба
      и предложил решение (ponytail, codebase-design: швы, тесты, файлы)
THEN  ⛔ СТОП №1: агент ждёт «ок» и до него не меняет ни одного файла

GIVEN пользователь сказал «ок» на ⛔ СТОП №1
WHEN  агент начинает работу
THEN  до первой строки кода он пишет в Delivery Queue строку 1 (CURRENT)
      с забронированными SPRINT-NN, FEAT-NNN, IDEA-NNN, статусом 🚧 реализация
      и пометкой режим: /l1-fast, и запись в историю роадмапа
AND   коммитит бронь отдельным коммитом chore(roadmap): reserve SPRINT-NN for /l1-fast —
      это точка начала спринта для продолжения и отклонения

GIVEN задача TASK-NN.MM готова и её тесты зелёные
WHEN  агент переходит к следующей
THEN  он коммитит её файлы по пути (git add <путь>): git ведёт журнал работы,
      отдельный файл-лог не нужен

GIVEN код написан
WHEN  агент готовит результат
THEN  до ⛔ СТОП №2 он выполняет весь список без исключений:
      tdd по срезам и скиллы стека из 40-skills-router.mdc;
      make ci с 0 ошибок;
      ponytail-review, code-review по двум осям (Standards и Spec);
      ponytail-audit и ponytail-debt;
      E2E: make test-e2e и живой прогон сценария;
      diagnosing-bugs с RED-тестом на каждый найденный баг;
      синхронизация docs/concept/ и правил; retro
AND   находки ревью он чинит сам и прогоняет проверки заново, не останавливаясь
AND   ⛔ СТОП №2: показывает результаты и пошаговый сценарий ручной проверки

GIVEN при ручной проверке человек нашёл проблему
WHEN  агент её починил
THEN  он прогоняет весь список проверок заново и снова выходит на ⛔ СТОП №2
```

Остановки по условию, кроме двух обязательных: сработал признак масштаба (до `⛔ СТОП №1`), вырос объём или ревью нашло вопрос, который решает только человек.

### US-4: Честные реестры после второго «ок»

**As a** пользователь **I want** полную цепочку документов, как в обычном пути **So that** история проекта не теряла фичи, сделанные быстро.

```
GIVEN пользователь сказал «ок» на ⛔ СТОП №2
WHEN  агент заполняет реестры без остановки
THEN  создаются и обновляются: IDEA-NNN в docs/ideas.md;
      FEAT-NNN в docs/backlog.md и короткая спека из 3 файлов в docs/specs/FEAT-NNN-<slug>/;
      README спринта docs/sprints/SPRINT-NN-<slug>/;
      TASK-NN.MM (1–3 задачи) и TASK-NN.99 с plan.md и summary.md
AND   в паспорте каждого документа есть строка «Режим | /l1-fast», даты настоящие,
      plan.md помечен «записан <дата> после реализации»
AND   агент ещё раз прогоняет make ci и doctor, переносит SPRINT-NN в «Завершённые спринты»
      и делает финальный коммит реестров docs(<scope>): record FEAT-NNN built in /l1-fast
      только своими файлами по пути (git add <путь>): код уже закоммичен по задачам,
      чужие правки из соседней вкладки в коммит не попадают; затем показывает итог
AND   пока реестры не заполнены, работа не считается завершённой
```

### US-5: Отклонение текущего спринта с откатом (`/l1-planning`)

**As a** пользователь **I want** отказаться от начатого спринта и вернуть код **So that** освободить позицию `CURRENT` честно, со следом в реестрах.

```
GIVEN в Delivery Queue есть спринт на позиции 1 (CURRENT)
WHEN  пользователь просит в /l1-planning отклонить текущий спринт
THEN  агент показывает коммиты спринта и незакоммиченные правки
AND   ⛔ СТОП: ждёт «ок» и до него ничего не меняет

GIVEN пользователь сказал «ок»
WHEN  агент откатывает изменения
THEN  код возвращается через git revert коммитов спринта, история не переписывается (без reset --hard)
AND   незакоммиченные правки агент не удаляет сам, а спрашивает, что с ними делать
AND   SPRINT-NN и его задачи получают статус ❌ отклонена
AND   FEAT-NNN получает ❌ отклонена или возвращается в 📋 в бэклоге — агент спрашивает пользователя
AND   строка спринта уходит из Delivery Queue в историю роадмапа с причиной
AND   документы спринта не удаляются: они остаются записью с причиной отказа
```

### US-6: Граница с соседними командами и правила

```
GIVEN правила 00/20/40-*.mdc, GLOSSARY.md, шаблон roadmap-template.md,
      скиллы l1-task и l1-hotfix и сводка AGENTS.md / CLAUDE.md на RU и EN
WHEN  описываются Roadmap Gate и правило двух остановок
THEN  /l1-fast назван исключением из Roadmap Gate только при пустой позиции CURRENT
AND   сказано, что в /l1-fast две остановки в чате без plan.md заранее
AND   граница ясна: /l1-chore — правки самого проекта, /l1-hotfix — баг продукта,
      /l1-fast — небольшая фича продукта
```

### US-7: Обновление уже настроенных проектов

```
GIVEN проект настроен на предыдущей версии L1DDER
WHEN  выполнен npx l1dder update на версию с /l1-fast
THEN  блок 🤖 из поля agent в assets/releases.json велит агенту добавить строку /l1-fast
      в защищённый l1dder/rules/40-skills-router.mdc, не меняя остальное
```

## 4. Ограничения и инварианты

- Русская и английская версии скиллов `/l1-fast` и `/l1-planning`, правил, шаблонов и гайдов меняются синхронно.
- EN-версия `/l1-planning` до этой фичи была короче RU в шагах 3–5 и Exit Gate (найдено в `TASK-05.02`). Расхождение **обязательно** устраняется в `TASK-05.03`, а страж RU/EN в `tests/planning-reject.test.ts` расширяется с ветки отклонения на весь скилл.
- В `/l1-fast` не ослабляется ни одна проверка и не пропускается ни один скилл из обычного пути: экономия только на остановках и на порядке документов.
- Релиз внутри `/l1-fast` не выпускается: как и везде, только по отдельной просьбе.
- Ломающих изменений нет: новые статусы `❌ отклонена` для `SPRINT-NN` и `TASK-NN.MM` только добавляются, `npx l1dder update` файлы в `docs/` не трогает.

## 5. Out of scope (Что НЕ делаем по принципу `ponytail` / YAGNI)

- Послабления в тестах и проверках, в том числе «по желанию».
- Автоматическая оценка масштаба по коду или диффу: хватает проверяемых признаков.
- Новые шаблоны и новые поля в шаблонах: строку `Режим | /l1-fast` добавляет скилл.
- Отклонение спринта, который не стоит на `CURRENT`, и откат через переписывание истории.
- Параллельная работа нескольких спринтов.
