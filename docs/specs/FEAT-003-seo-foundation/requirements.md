## 1. Контекст и связь с идеей `IDEA-003`

Фича реализует `IDEA-003`: сейчас у сайта нет `sitemap.xml`, превью для соцсетей, канонических адресов и связки RU/EN, а описание страниц общее. На GitHub нет тем, а его описание устарело. Фича даёт поисковикам и ИИ-ассистентам правильную информацию о проекте и не должна сломать работающий сайт.

## 2. Целевая аудитория / Роли

- Разработчик, который ищет способ вести проект с ИИ-агентами или помнит название L1DDER.
- Поисковые системы (Google, Яндекс) и ИИ-ассистенты, читающие сайт.
- Автор проекта, который подключает сайт к панелям поисковиков и выпускает релиз.

## 3. User Stories и Acceptance Criteria

### US-1: Понятная страница в выдаче

**As a** человек, ищущий инструмент
**I want** видеть в выдаче понятный заголовок и описание страницы
**So that** я сразу понимаю, подходит ли она мне

```
GIVEN любая из 18 страниц сайта (9 RU + 9 EN)
WHEN  открываю код собранной страницы
THEN  у неё свой <title> и своё meta description, не повторяющиеся на других страницах
AND   есть канонический адрес и ссылки hreflang на обе языковые версии и x-default
```

### US-2: Полный список страниц для поисковиков

**As a** поисковая система
**I want** получить полный список страниц
**So that** ни одна страница не потеряется при индексации

```
GIVEN собранный сайт
WHEN  читаю sitemap.xml
THEN  в нём ровно 18 адресов, все с путём /l1dder/, и каждый ведёт на существующую страницу
```

### US-3: Аккуратное превью ссылки

**As a** человек, получивший ссылку на сайт
**I want** видеть заголовок, описание и картинку
**So that** ссылка выглядит достойно в мессенджере или соцсети

```
GIVEN любая страница сайта
WHEN  читаю её Open Graph и Twitter-теги
THEN  заголовок и описание совпадают со страницей, а картинка 1200×630 реально открывается
```

### US-4: Правильные витрины

**As a** посетитель GitHub или npm
**I want** сразу понять, что это за проект, и найти его по словам из своей задачи
**So that** я не упираюсь в устаревшее описание и знаю, как произносится название

```
GIVEN страницы проекта на GitHub и npm
WHEN  смотрю описание, темы и начало README
THEN  описание актуально, нет слов «public mirror», заданы темы
AND   в README один раз указано произношение: по-русски «лидер», по-английски "leader" или "l'oneder"
```

### US-5: `llms.txt` для ИИ-ассистентов

**As a** ИИ-ассистент, читающий сайт
**I want** получить короткую карту страниц в простом тексте
**So that** я правильно рассказываю о L1DDER и даю верные ссылки

```
GIVEN собранный сайт
WHEN  открываю /l1dder/llms.txt
THEN  в нём название, краткое описание и все 18 страниц со ссылками и описаниями
AND   каждая ссылка ведёт на существующую страницу
```

### US-6: Сайт не сломан (обязательный гейт перед релизом)

**As a** автор проекта
**I want** строго убедиться перед релизом, что сайт работает не хуже, чем до спринта
**So that** SEO-правки не навредят текущим читателям

```
GIVEN снимок текущего сайта, сделанный до первых правок
WHEN  проверяю готовую production-сборку с базовым путём /l1dder/
THEN  у всех 18 страниц те же адреса и заголовки H1, текст и число диаграмм не уменьшились
AND   все внутренние ссылки, якоря и файлы существуют
AND   в браузере на всех страницах нет ошибок консоли и диаграммы отрисованы
AND   работают поиск, меню, переключатель языка, светлая и тёмная темы и ширина телефона
AND   при любом сбое релиз не запускается
```

## 4. Ограничения и инварианты

- Адреса существующих страниц не меняются.
- Без ручного отчёта по гейту US-6 и подтверждения человека релиз `v1.0.3` не запускается.
- Запись в `assets/releases.json` и выпуск только по прямой просьбе пользователя с названной версией.
- `L1DDER` не обещает рост позиций: фича отвечает только за корректность данных.
- Вход в панели поисковиков выполняет сам автор проекта.

## 5. Out of scope (Что НЕ делаем по принципу `ponytail` / YAGNI)

- Новые статьи и страницы, Хабр и другие внешние упоминания.
- Свой домен и `robots.txt` (корень `ledvanoff.github.io` не относится к этому репозитории).
- Изменение текстов на страницах и первого экрана.
- JSON-LD и `llms-full.txt`.
