## 1. Цель задачи и фильтр `ponytail` (6-Step Decision Ladder)

**Цель:** в `/l1-planning` на RU и EN появляется ветка «Отклонить текущий спринт». Она честно освобождает позицию `1 (CURRENT)`: откатывает код спринта через `git revert`, не трогая историю, ставит статус `❌ отклонена` и оставляет документы спринта как запись с причиной. Это `US-5` из [`requirements.md`](../../../../specs/FEAT-006-fast-mode/requirements.md) и решение [`ADR-0002`](../../../../adrs/ADR-0002-sprint-rejection-rollback.md). Отказ `/l1-fast` при активном спринте теперь указывает на путь, который существует.

**Git как журнал `/l1-fast` (добавлено на `⛔ СТОП №1` по вопросу пользователя о микрологе).** Раньше `/l1-fast` ничего не коммитил до конца, и прерванный быстрый спринт нельзя было отделить от правок соседней вкладки. Теперь:
- **Шаг 4:** бронь сразу коммитится отдельным коммитом `chore(roadmap): reserve SPRINT-NN for /l1-fast`. Это точка начала спринта.
- **Шаг 5:** после каждой задачи с зелёными тестами — коммит её файлов по пути.
- **Шаг 7:** финальный коммит содержит только реестры.

Отдельный файл-лог не нужен: он устаревал бы, а git уже хранит то же самое. Отклонение одинаково для обычного и быстрого спринта.

**Как устроена ветка.** Ветка срабатывает, когда пользователь просит отклонить текущий спринт. Шаги 1–5 обычного планирования в ней не выполняются.

| Шаг | Что делает агент | Готово, когда |
|-----|------------------|---------------|
| О1. Что будет отменено | Читает строку `1 (CURRENT)` и README спринта. Начало спринта — коммит, который впервые добавил `SPRINT-NN` в `docs/roadmap.md` (`git log -S "SPRINT-NN" -- docs/roadmap.md`). Перечисляет коммиты после него; коммиты хотфиксов и служебных правок (`HOTFIX-NNN`, `CHORE-NNN` из `docs/backlog.md`) по умолчанию исключает. Показывает незакоммиченные правки (`git status`) | Список коммитов к откату, исключения и незакоммиченные правки собраны |
| О2. Карточка + `⛔ СТОП` | Спринт, причина, коммиты к откату, исключённые коммиты, незакоммиченные правки и что с ними делать, судьба `FEAT-NNN`: `❌ отклонена` или возврат в `📋 в бэклоге` | «ок» получен |
| О3. Откат кода | Незакоммиченные правки — только по выбору пользователя: агент их сам не удаляет. Затем `git revert --no-commit` коммитов спринта от новых к старым, документы возвращаются из `HEAD` (`git checkout HEAD -- docs/`), `make ci`. При конфликте — остановка и вопрос человеку. `reset --hard` и переписывание истории запрещены | Код без изменений спринта, `make ci` зелёный |
| О4. Статусы | `SPRINT-NN` и все его задачи, включая закрытые (их код откачен), получают `❌ отклонена`. В README спринта — «Итог спринта» с причиной. В `docs/backlog.md` — `FEAT-NNN` по выбору из карточки; если `FEAT-NNN` отклонена и у `IDEA-NNN` нет других фич в работе — идея возвращается в `📋 нереализована`. В `docs/roadmap.md` — строка уходит из `Delivery Queue`, следующий спринт встаёт на `1 (CURRENT)`, запись в «Историю» с причиной. Документов, которых ещё нет (у брони `/l1-fast` до Шага 7), агент не создаёт | Все реестры согласованы |
| О5. Коммит + Exit Gate | Один коммит только своих файлов по пути: `revert(<scope>): reject SPRINT-NN` | Чек-лист отмечен |

**Статус `❌ отклонена`** у `SPRINT-NN` и `TASK-NN.MM`:
- в `20-workflow.mdc` (справочник статусов);
- в поле статуса `sprint-template.md`.

В `backlog-template.md` этот статус уже есть.

**Фильтр `ponytail`:**
- **Что переиспользуем:**
  - готовые команды git (`git log -S`, `git revert --no-commit`, `git checkout HEAD -- docs/`): своего кода отката нет;
  - карточку с одной `⛔`, как в `/l1-chore`;
  - стиль контрактных тестов `tests/fast-skill.test.ts`;
  - статус `❌ отклонена`, который уже есть у `IDEA` и `FEAT`.
- **От чего отказываемся:**
  - кода в CLI;
  - отклонения не текущего спринта (вне `requirements.md`);
  - нового статуса для `FEAT-NNN.MM` в спеке: шаги спеки остаются как есть, отказ записан в спринте и бэклоге;
  - правок шпаргалки `03-CHEATSHEET.md` (это `TASK-05.04`).
- **Публичные швы (`Pre-agreed Test Seams`):**
  - `Seam 4` — `tests/planning-reject.test.ts`: текст `assets/i18n/{ru,en}/skills/l1-planning/SKILL.md`, `rules/20-workflow.mdc` и `templates/sprints/sprint-template.md` на RU и EN.

## 5. Риски и открытые вопросы

- **Поиск начала спринта.** Коммит, который впервые добавил `SPRINT-NN` в роадмап, — это коммит планирования. Если спринт планировался вместе с чем-то ещё в одном коммите, этот коммит в откат не попадёт: откатываются только коммиты *после* него. Документы и так остаются, а код в коммите планирования обычно не меняется.
- **Документы и отклонённые коммиты.** Если коммит спринта менял и код, и `docs/`, документы всё равно возвращаются из `HEAD`. Так задумано: документы остаются записью.
- **Код вне `docs/`, который откатывать не надо** (например, сгенерированные файлы), попадёт в откат вместе со спринтом. Агент показывает список коммитов до `⛔`, и пользователь может исключить коммит.
- **Возврат `IDEA-NNN` в `📋 нереализована`** при отклонённой фиче в спеке не был описан. Добавляю его, иначе идея висит в `🚧 реализация` без работы. Если не нужно, уберу на этой остановке.
