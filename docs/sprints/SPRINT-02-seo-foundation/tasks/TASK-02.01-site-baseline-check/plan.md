## 1. Цель задачи и фильтр `ponytail` (6-Step Decision Ladder)

**Цель:** До первых SEO-правок зафиксировать состояние всех 18 страниц и получить автоматическую проверку, которая находит поломки готовой сборки сайта (`US-6` фичи `FEAT-003`, идея `IDEA-003`).

**Фильтр `ponytail` (заполнить до написания кода):**
- **Что переиспользуем из репозитория / платформы / установленных пакетов:** `node:fs`, `node:path`, встроенный `URL`, предсказуемую разметку VitePress, стиль и аргументы `scripts/render-release-notes.mjs`, цель `make test-e2e`.
- **От чего намеренно отказываемся (`Ponytail skipped` / YAGNI):** новые зависимости (`cheerio`, `linkinator`), скриншотные сравнения, проверка внешних ссылок, запуск браузера в CI.
- **Публичные швы для тестирования (`Pre-agreed Test Seams`):** только `node scripts/check-site.mjs [distDir] [--baseline <file>] [--write-baseline <file>]`: код выхода и сообщение на маленьких примерах сборки во временной папке.

## 3. Критерии готовности (DoD)

**Агент проверяет (исполняемые команды):**

| # | Критерий | Точная команда / способ проверки |
|---|----------|----------------------------------|
| 1 | Проверка ловит битую ссылку, битый якорь, отсутствующий файл и потерянный `/l1dder/` | `npx vitest run tests/check-site.test.ts`: каждый случай падает до реализации |
| 2 | Сравнение ловит пропавшую или лишнюю страницу, изменённый H1, уменьшение текста и диаграмм, потерянную ссылку меню | `npx vitest run tests/check-site.test.ts` |
| 3 | До исправления реальная сборка даёт ровно 2 ошибки якорей, после исправления ни одной | `node scripts/check-site.mjs` до и после Шага 4 |
| 4 | В снимке ровно 18 страниц, `404.html` не входит | Чтение `site-baseline.json` |
| 5 | Снимок совпадает со снимком живого сайта | `diff` снимка и временного снимка с `ledvanoff.github.io/l1dder/` |
| 6 | Сравнение текущей сборки со снимком проходит | `make site-gate` |
| 7 | Линтер, типы, тесты, сборка и сайт проходят без ошибок, включая тесты на Windows в CI | `make ci`, CI после пуша |

**Пользователь проверяет (при необходимости):**

- На главной странице кнопка про манифест скиллов прокручивает страницу `agents-cli` к нужному разделу (проверим в браузере перед релизом).

## 4. Артефакты и границы Scope

**Трогаем (создаём или меняем только эти файлы):**
- `scripts/check-site.mjs` — структурная проверка, сравнение и запись снимка.

- `Makefile` — проверка в `test-e2e`, новая цель `site-gate`.
- `docs/sprints/SPRINT-02-seo-foundation/site-baseline.json` — снимок сайта до правок.
- `site/index.md`, `site/en/index.md` — исправление двух битых якорей.
- `l1dder/rules/30-tech-stack.mdc` — новый скрипт и цель `make site-gate` в описании стека (с синхронизацией в папки агентов при сборке).
- `docs/specs/FEAT-003-seo-foundation/design.md` — сравнение со снимком вынесено в `make site-gate`.

**НЕ трогаем (вне Scope):**
- `site/.vitepress/config.mts`, тексты страниц, метаданные и `sitemap.xml` — это `TASK-02.02`.
- `assets/i18n/`, `src/`, `assets/releases.json`, `publish.yml`, `docs.yml`.

## 5. Риски и открытые вопросы

- **Сравнение вынесено из `make ci`.** Постоянное сравнение со снимком мешало бы будущим правкам документации, например сокращению текста. Поэтому в `make ci` остаётся структурная проверка, а `make site-gate` обязателен в DoD задач этого спринта и в гейте `TASK-02.99`.
- **Разметка VitePress.** Проверка опирается на регулярные выражения по разметке VitePress: при смене его мажорной версии разбор может потребовать правки. Отсутствие H1 или текста на странице проверка считает ошибкой, чтобы сбой был громким.
- **Что не ловится.** Проверка не видит поломок, заметных только в браузере: ошибки JavaScript и отрисовку диаграмм. Их закрывает браузерный гейт в `TASK-02.99`.
