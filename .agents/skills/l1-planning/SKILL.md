# L1DDER — Цепочка 3: Планирование Роадмапа (`/l1-planning`)

> **ПРАВИЛО ДЛЯ МОДЕЛИ:** Выполняй инструкцию строго по шагам 1 → 2 → 3 → 4 → 5. `docs/roadmap.md` — это главный источник истины проекта. Никогда не редактируй файлы до получения слова «ок» от пользователя на Шаге 3.
>
> **Отклонение спринта:** если пользователь просит отклонить текущий спринт и откатить его изменения, Шаги 1–5 не выполняй и иди в раздел «ВЕТКА: Отклонить текущий спринт» в конце файла.

## Правило присвоения ID при планировании (копируй символ-в-символ)

Когда кандидат спринта из фичи `FEAT-NNN` (родитель `IDEA-NNN`) ставится в очередь `Delivery Queue` файла `docs/roadmap.md`:
1. Спринт получает двузначный ID `SPRINT-NN` (`SPRINT-01`, `SPRINT-02`...).
2. Папка спринта называется строго `docs/sprints/SPRINT-NN-<slug>/` (начинается с `SPRINT-NN-`).
3. Каждый шаг спеки `FEAT-NNN.MM` получает парный ID задачи спринта `TASK-NN.MM`:
   - `FEAT-NNN.01` → `TASK-NN.01`
   - `FEAT-NNN.02` → `TASK-NN.02`
   - `FEAT-NNN.99` → `TASK-NN.99` *(обязательная финальная задача Doctor Checklist)*
4. Статус фичи `FEAT-NNN` в `docs/backlog.md` меняется с `📋 в бэклоге` на `🗓 запланирована`.

## ВЕТКА: Отклонить текущий спринт

Отклонение честно освобождает позицию `1 (CURRENT)`: код спринта откатывается без переписывания истории, а документы спринта остаются записью с причиной отказа.

### О1: Покажи, что будет отменено

1. Прочитай `docs/roadmap.md`, `docs/backlog.md` и README спринта на позиции `1 (CURRENT)` (у брони `/l1-fast` README ещё нет).
2. Найди начало спринта — коммит, который первым добавил `SPRINT-NN` в роадмап: `git log -S "SPRINT-NN" --format="%h %s" -- docs/roadmap.md` (самый старый в выводе). У обычного спринта это коммит планирования, у быстрого — коммит брони.
3. Выпиши коммиты после него: `git log --format="%h %s" <начало>..HEAD`. Коммиты хотфиксов и служебных правок (`HOTFIX-NNN`, `CHORE-NNN` из `docs/backlog.md`) по умолчанию исключи из отката.
4. Покажи незакоммиченные правки: `git status`.

### О2: Покажи карточку и ОСТАНОВИСЬ (`⛔ СТОП`)

1. Выведи в чат карточку:

```markdown
### Отклонение спринта `SPRINT-NN` (`FEAT-NNN` ← `IDEA-NNN`)

| Поле | Значение |
|------|----------|
| **Причина** | [Почему отклоняем — со слов пользователя] |
| **Начало спринта** | `<hash>` [сообщение коммита] |
| **Откатываем (`git revert`)** | `<hash>` [сообщение], ... |
| **Не откатываем** | `<hash>` `HOTFIX-NNN` / `CHORE-NNN`, ... или «—» |
| **Незакоммиченные правки** | [Файлы из `git status`] → оставить / убрать в `git stash` / закоммитить в спринт и откатить вместе с ним |
| **Фича `FEAT-NNN`** | `❌ отклонена` или вернуть в `📋 в бэклоге` для нового спринта |
| **Документы спринта** | Остаются как запись со статусом `❌ отклонена` |
```

2. Спроси: *«Отклоняем `SPRINT-NN` и откатываем его код (ок / правки)?»* — и жди ответа. До слова «ок» ничего не меняй.

### О3: Откати код спринта (ТОЛЬКО после «ок»)

1. Незакоммиченные правки обработай только так, как выбрал пользователь в карточке: оставить, убрать в `git stash` или закоммитить в спринт и откатить вместе с ним.
2. Откати коммиты из карточки от новых к старым одним набором, без отдельного коммита на каждый: `git revert --no-commit <hash-новый> ... <hash-старый>`. История сохраняется; `reset --hard` и переписывание истории не используй, они теряют работу без следа.
3. Верни документы, которые затронул откат, в состояние до него: `git diff --cached --name-only -- docs/ | xargs git checkout HEAD --`. Берутся только пути из отката, поэтому незакоммиченные правки в `docs/`, которые пользователь решил оставить (например, спека из соседней вкладки), не пострадают. Код спринта уходит, его документы остаются записью.
4. Если git сообщил о конфликте, остановись: покажи файлы с конфликтом и спроси пользователя, как его разрешить. Сам конфликт не разрешай.
5. Запусти `make ci`: код без спринта должен собираться и проходить тесты, 0 ошибок.

### О4: Обнови реестры

Обнови только те документы, которые уже есть (у брони `/l1-fast` их нет, кроме строки роадмапа). Ничего не удаляй, даты пиши настоящие.

1. `docs/sprints/SPRINT-NN-<slug>/README.md` — статус спринта `❌ отклонена`, у всех задач `TASK-NN.MM`, включая закрытые, `❌ отклонена`: их код откачен. В «Итоге спринта» — причина и список откаченных коммитов.
2. `docs/backlog.md` — те же статусы у `SPRINT-NN` и его задач; у `FEAT-NNN` в Таблице 1 и Разделе 2 — выбор из карточки: `❌ отклонена` или `📋 в бэклоге` (ссылку на `SPRINT-NN` оставь как историю).
3. `docs/ideas.md` — если `FEAT-NNN` отклонена и у `IDEA-NNN` не осталось других фич в работе, верни идею в `📋 нереализована` и допиши в карточку причину.
4. `docs/roadmap.md` — убери строку `SPRINT-NN` из `Delivery Queue` и поставь следующий спринт на `1 (CURRENT)` (если очередь пуста — `—`), обнови «Текущий фокус» и добавь строку в «5. История изменений Роадмапа»: `SPRINT-NN` (`FEAT-NNN` ← `IDEA-NNN`) отклонён, причина, откаченные коммиты.

### О5: Закоммить отказ и проверь себя

1. Закоммить откат и реестры одним коммитом: `revert(<scope>): reject SPRINT-NN`, в теле — причина и откаченные коммиты. В коммит добавь только свои файлы, по пути (`git add <путь>`): откаченный код и обновлённые реестры. Чужие правки, например спеку из соседней вкладки, оставь как есть.
2. Пушь, только если пользователь попросил или так принято в проекте (`l1dder/rules/30-tech-stack.mdc`).
3. Проверь чек-лист и сообщи пользователю, что откачено, какой спринт теперь на `1 (CURRENT)` и что стало с фичей и идеей:
   - [ ] «Ок» на карточку получен до отката?
   - [ ] Откачены только коммиты из карточки, история не переписана, `make ci` зелёный?
   - [ ] Документы спринта на месте, со статусом `❌ отклонена` и причиной?
   - [ ] `SPRINT-NN` убран из `Delivery Queue`, запись в истории роадмапа есть, статусы фичи и идеи согласованы?
