# L1DDER — Цепочка 1: Идея (`/l1-idea`)

> **ПРАВИЛО ДЛЯ МОДЕЛИ:** Выполняй инструкцию строго по шагам 1 → 2 → 3 → 4 → 5. Не пропускай шаги. Никогда не редактируй `docs/ideas.md` до того, как пользователь явно напишет «ок» на Шаге 3.

---

## Справочник форматов (копируй символ-в-символ)

- **Формат ID идеи:** `IDEA-NNN` (три цифры с ведущими нулями: `IDEA-001`, `IDEA-002`, `IDEA-003`...).
- **Формат якоря карточки:** `#idea-nnn` (строчными буквами: `#idea-001`, `#idea-002`...).
- **Допустимые приоритеты:** `P0` | `P1` | `P2` | `P3`
- **Допустимые статусы `IDEA-NNN`:**
  - `📋 нереализована` *(статус при создании новой идеи)*
  - `🚧 реализация`
  - `✅ реализована`
  - `❌ отклонена`

---

## ШАГ 1: Прочитай входные файлы

Вызови инструмент `Read` для файлов:
1. `docs/ideas.md` *(если файла ещё нет — прочитай `l1dder/templates/ideas/ideas-template.md`)*.
2. `docs/concept/idea.md` + `l1dder/GLOSSARY.md` *(чтобы знать контекст и единый доменный словарь проекта)*.

---

## ШАГ 2: Вычисли новый ID (`IDEA-NNN`)

1. Посмотри на таблицу «1. Реестр идей» в `docs/ideas.md`.
2. Найди наибольший номер `IDEA-NNN` и прибавь `+1` (если последний `IDEA-003` → твой новый код `IDEA-004`; если таблица пустая или файла нет → `IDEA-001`).
3. Проверь, нет ли в таблице дублирующей идеи. Если есть — сообщи об этом пользователю и предложи дополнить существующую `IDEA-NNN`.

---

## ШАГ 3: Брейншторм по дисциплине `grilling` + `domain-modeling` и черновик карточки (`⛔ СТОП`)

1. **Правило поиска фактов (`grilling`):** Искать факты в коде, спеках и документации — твоя задача, никогда не перекладывай её на человека. У человека спрашивай **только продуктовые решения**.
2. **Формат опроса по дереву решений (`Design Tree Frontier`):** Если в идее есть развилки, задавай только независимые вопросы текущего уровня дерева решений в формате:
   ```markdown
   ❓ **Q1 — [Короткое название развилки]**: [Суть выбора и 2–3 варианта с опорой на факты]
   ➡️ **Рекомендация:** [Твой рекомендуемый вариант по принципу ponytail — сформулируй так, чтобы ответ «ок» его принимал]
   ```
   *(Если для выбора нужно увидеть механику/UI глазами — предложи собрать быстрый одноразовый прототип).*
3. **Доменный словарь (`domain-modeling`):** Если в ходе обсуждения рождается новый доменный термин — зафиксируй его точное имя и определение в карточке.
4. Выведи пользователю черновик карточки строго по шаблону ниже:

```markdown
### Черновик для Банка Идей (`docs/ideas.md`)

| Поле паспорта | Значение |
|---------------|----------|
| **ID идеи** | `IDEA-NNN` |
| **Название** | [Короткое понятное название] |
| **Приоритет** | `P0` / `P1` / `P2` / `P3` |
| **Статус** | `📋 нереализована` |
| **Связанные фичи (`FEAT-NNN`)** | — |

**Суть идеи и ценность:**
[2–3 предложения]

**Ключевые сценарии:**
- [Сценарий 1]
- [Сценарий 2]

**Новые термины доменного словаря (`domain-modeling`, если есть):**
- **[Термин]** — [определение в 1 строку]

**Границы объёма (`ponytail` / YAGNI):**
- **Делаем в базе:** [...]
- **Откладываем / НЕ делаем:** [...]
```

5. ⛔ **СТОП:** Спроси пользователя: *«Утверждаем карточку `IDEA-NNN` (и ответы на `❓ Q1..`) для записи в `docs/ideas.md` (ок / правки)?»* и прекрати выполнение до ответа.

---

## ШАГ 4: Запиши `IDEA-NNN` в `docs/ideas.md` (ТОЛЬКО после слова «ок»)

1. Если `docs/ideas.md` ещё не существует — создай его по шаблону `l1dder/templates/ideas/ideas-template.md`.
2. **Действие 4.1 (Таблица 1):** Добавь новую строку в конец таблицы `## 1. Реестр идей (Сводная таблица)` строго по образцу:

```markdown
| [`IDEA-001`](#idea-001) | Мгновенный поиск и фильтрация по каталогу | P0 | 📋 нереализована | — | 2026-10-21 |
```

3. **Действие 4.2 (Раздел 2):** Добавь полную карточку в конец раздела `## 2. Карточки идей` строго по образцу:

```markdown
### IDEA-001: Мгновенный поиск и фильтрация по каталогу {#idea-001}

| Поле паспорта | Значение |
|---------------|----------|
| **ID идеи** | `IDEA-001` |
| **Приоритет** | `P0` |
| **Статус** | `📋 нереализована` |
| **Связанные фичи (`FEAT-NNN`)** | — |
| **Дата создания** | 2026-10-21 |

#### Суть идеи и ценность
Дать пользователю возможность находить нужные элементы по названию и тегам за миллисекунды с сохранением фильтров в URL.

#### Ключевые сценарии / Как это работает
- Пользователь вводит запрос в строку поиска и сразу видит отфильтрованный список с подсветкой совпадений.
- При выборе тега фильтр сохраняется в query-параметрах URL, чтобы ссылкой можно было поделиться.

#### Итоги брейншторма и ограничения (`ponytail` / YAGNI)
- **Что входит в базовый объём:** поиск по подстроке и фильтр по тегам с синхронизацией в URL.
- **Что откладываем / не делаем:** отдельный поисковый движок (Elasticsearch не нужен до 10 000 записей).
```

## ШАГ 5: Чек-лист самопроверки перед ответом (Exit Gate)

Перед тем как написать пользователю «Готово», проверь 4 пункта:
- [ ] 1. Код в таблице (`IDEA-NNN`) и в заголовке карточки (`### IDEA-NNN: ... {#idea-nnn}`) совпадают символ-в-символ?
- [ ] 2. Статус записан ровно как `📋 нереализована`?
- [ ] 3. Приоритет записан как одно из `P0`, `P1`, `P2`, `P3`?
- [ ] 4. В колонке «Связанные фичи (`FEAT-NNN`)» стоит `—`?

После проверки сообщи пользователю:
- *«Идея `IDEA-NNN` добавлена в `docs/ideas.md` со статусом `📋 нереализована`.»*
- *«Следующий шаг: вызови `/l1-feature IDEA-NNN` для проработки спеки или `/l1-planning` для постановки идеи в очередь Роадмапа.»*
